# cherepaha: линейный счёт с учётом истории

Техническая реализация задания 4++. Предметная область — студенческая жизнь:
экзамены, дедлайны, домашка, сон, кофе и каникулы. Набор — 30 мемов
с подписями (imgflip.com), по одному на ситуацию: от паники перед экзаменом
(01_panic.jpg) до победы после сдачи (02_success.jpg). Запасной ответ —
30_neutral.jpg.

## Правило

Берём последние k <= 5 сообщений, нумеруем от старого к новому: 1..k.
Каждую реплику нормализуем стандартной функцией проекта. Повторы одной леммы
внутри сообщения удаляем с сохранением порядка первого появления.

Для каждого мема m считаем:

    score(m) = sum(i * sum(weight(m, word) for word in unique_words(message_i)))

Свежая реплика имеет больший вес. Побеждает максимальный положительный счёт.
При равенстве — меньший номер файла. Если все счета <= 0, возвращается fallback.
Каждый вызов вычисляет результат заново из входной истории: общего состояния
диалогов нет, разные пользователи не влияют друг на друга.

История влияет на оценку, но не обязана менять ответ в каждом случае.
Удаление старой реплики может поменять победителя, а также перенумеровывает
оставшиеся реплики. Отрицание, сарказм и порядок слов модель не распознаёт:
это явные ограничения модели мешка слов.

## features.txt

JSON: `fallback` — имя запасного файла; `memes` — 30 записей с `file` и `weights`.
Каждый ключ weights — одно слово; значения — конечные числовые веса.
Признаки автоматически нормализуются, повтор одной леммы для мема запрещён.
Допустимы отрицательные веса для нежелательных признаков.

При каждом выборе файл читается целиком. Разбор JSON и построение обратного
индекса кешируются по содержимому (одна версия). Поэтому изменение признаков
действует на следующий вызов даже без перезапуска процесса и изменения Python.
Некорректная конфигурация вызывает ошибку, а не скрывается случайным ответом.

## Структуры данных и сложность

- dict: слово -> список пар (индекс мема, вес).
- dict для удаления повторов слов в реплике с сохранением порядка.
- list из 30 чисел: счета; линейный поиск максимума.

Обозначения: F — размер features.txt, L — размер входа в выбранном окне,
E — количество связей слово-мем в конфигурации, K — количество обработанных
попаданий в обратном индексе, M = 30. C_norm — стоимость нормализации текста.

Обычный вызов при прогретом кеше: O(F + C_norm + L + K + M) в среднем
для хеш-таблиц. Чтение и хеширование файла стоят O(F), даже при попадании в кеш.
При смене конфигурации дополнительно нужны разбор JSON, нормализация признаков,
построение индекса и сортировка имён: O(F + C_norm_features + E + M log M).

Индекс занимает O(E + M), обработка запроса — O(F + L + M) памяти,
не считая внутреннего словаря pymorphy3, общего для всего приложения.
Картинки в память не загружаются. Веса не являются вероятностями.

## Проверка

Из корня репозитория:

```bash
uv run python algorithms/cherepaha/test.py -v
uv run python -m unittest discover -s tests -v
uv run local-chat cherepaha
```

Примеры для проверки истории:

- `Завтра экзамен, паника` -> `да`: 01_panic.jpg
- `Сдал экзамен, победа` -> `да`: 02_success.jpg

Тесты также проверяют обновление конфигурации, доступность всех 30 ответов,
повторы слов, разрешение равенства, морфологию, длину окна и загрузку оболочкой.
